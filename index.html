帮助 · 模型使用方法

从零开始配置大模型，快速跑通提示词优化流程

一、快速开始

  1. 打开「设置」页，按下方任一方式配置好模型（首次使用必须）。
  2. 进入「新建优化」，输入你的初步想法，点击「开始优化」。
  3. 回答 AI 提出的追问（也可直接跳过），等待生成结构化提示词。
  4. 在结果区可复制、评分、切换框架，或导出为 MD / JSON / PDF。
  5. 已有成稿提示词？进「⚡ 提示词优化」粘贴进去，一键精修并对比原文。

二、在线 API 模型（推荐）

在「设置」页点击对应的预设按钮会自动填入端点与模型，只需再粘贴你自己的 API Key，然后保存。

模型名称可自由换成该服务商任意 OpenAI 兼容模型（如 deepseek-reasoner、qwen-max、glm-4-plus）；也可填入任意第三方中转站点的 OpenAI 兼容地址。

三、Ollama 本地模型（免费 · 需本地运行）

  1. 在 ollama.com 下载安装 Ollama 并保持运行。
  2. 终端执行 ollama pull qwen2.5:7b 下载模型（可换成其他模型名，如 llama3.1:8b）。
  3. 在「设置」页点「Ollama 本地」预设（端点 http://localhost:11434/v1，密钥留空），模型名填你 pull 的模型，保存即可。

四、离线模型（无需 API · 完全本地）

在「设置」页把「运行引擎」切换为「本地离线」，然后在「离线模型管理」中选择模型卡片并点击「下载加载」：

  • Qwen2.5-1.5B（约 1.5GB）：中文能力优秀，提示词优化效果最好，推荐。
  • Phi-3.5 Mini（约 2.2GB）：英文能力强，通用推理好。
  • SmolLM2-1.7B（约 1.0GB）：最轻量，适合低内存设备。

首次下载需联网，之后完全离线运行。支持 WebGPU 硬件加速；设备不支持时自动降级为 WASM（纯 CPU），加载与推理会更慢。8GB 以上内存推荐 Qwen2.5-1.5B，低内存设备选 SmolLM2。

五、常见问题

生成时报「请求失败 / Failed to fetch」？检查 API 端点、密钥与模型名是否填写正确，并确认网络可达；离线模式则不受影响。
离线模型下载到一半失败？检查网络后重新点击下载即可重新尝试；加载慢可换更小的模型。
生成的提示词效果不满意？换一个框架（CO-STAR / CREATE / BROKE）、在「框架对比」中多框架生成，或把「追问灵敏度」调高。
「提示词优化」和「新建优化」有什么区别？「新建优化」是从一个模糊想法生成提示词；「提示词优化」是精修一条你已经写好的提示词，会诊断任务 / 上下文 / 参数约束 / 输出格式四个维度并补齐，且本地规则模式不联网也能用。
如何备份/迁移数据？设置页「导出全部数据」，新设备上「导入数据」即可。
API 密钥安全吗？密钥仅保存在本机浏览器存储中，不会上传到任何服务器（云同步会同步设置内容，请妥善保管导出文件）。

更新文件夹：--

  1. 侧边栏有独立的「⟳ 检查更新」菜单：发现新版本时右侧会冒红点，单击即可自动下载并安装——纯界面更新无需退出软件，自动刷新生效。
  2. 通常不需要任何配置。客户端会依次从「你填写的更新源 → 清单里的内置分发源 → 本机部署地址 → 程序目录下的 version.json → 更新文件夹」自动寻找版本清单，找到就检测。
  3. 需要指定固定更新源时：在「设置 → 软件更新源地址」填入发布目录的访问地址（放着 version.json 的那个目录），保存后点「测试连接」验证。
  4. 完全离线也可更新：把 version.json 和更新包一起放进更新文件夹（点下方「打开更新文件夹」）。
  5. 应用启动与运行中每 45 秒自动检查一次，红点出现即代表可更新。

上方「更新源」一行会直接告诉你实际用的是哪一处清单、清单上是哪个版本。 若显示"检查失败"，原因会写在这里（例如清单缺少安装包字段），不会再笼统显示"最新版本"。

离线模型大文件不参与更新流程，更新后已下载的模型继续可用。浏览器/PWA 版无需更新。

首次配置云同步

1. 打开 supabase.com 注册并创建一个免费项目（等待初始化完成）。

2. 在项目里打开 SQL Editor，粘贴并执行以下 SQL 建表：

create table if not exists public.pf_records (
  id text primary key,
  ns text not null,
  updated_at timestamptz not null,
  payload jsonb not null
);
alter table public.pf_records enable row level security;
create policy "pf_anon_all" on public.pf_records
  for all using (true) with check (true);

3. 回到本应用设置页，填写 Supabase URL 与 anon key（Dashboard → Settings → API），给各设备填相同的空间名，保存后点"立即同步"。

安全说明：anon key 本身是公开的，数据靠"空间名"隔离，请使用不易被猜到的空间名，勿与其他服务共用。
